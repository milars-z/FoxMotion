## GPU 与推理

RunPod A40 46,068 MiB，7.65 vCPU，cgroup RAM 上限 49,999,998,976 字节（46.57 GiB）。Ubuntu 24.04，Python 3.12.3，PyTorch 2.8.0+cu129，CUDA 12.9，ComfyUI fe4195f7f4275f2626cbafc703acc3ddde1e5490。

Phase 2 对照只切换节点缓存。首尾帧 FL2VA 完整 INT8 基座，标名 8-step 的 FL2V Turbo 权重，部署图实际使用六个采样区间。320×192、24 fps、目标 0.9 秒，输出 22 帧。冷启动指新 Comfy 进程，宿主文件页与卷缓存未清空。每种配置连续两次，热任务使用变化的提示词和种子，每格一个样本。

热任务耗时从 1008.24 降至 180.70，实测减少 82.1%，约 5.58 倍。两次冷任务相差不到 1%，样本不足以归因。四次 RAM 采样峰值均达 46.57 GiB，出现内存上限回收压力，OOM 和 OOM kill 增量均为零。保留 classic、DynamicVRAM、禁用 pinned memory 与 async offload 两项参数，空闲主动释放默认关闭。前两项 offload 开关影响主机内存及传输方式；模型驻留还取决于图缓存引用和原生显存调度。未对 highvram 或强制全量驻留作实测结论。[逐阶段方法与 PCIe 记录](RUNPOD_PHASE2.md)

## 保密模式的真实验收

用户通过网页两次各上传三张合成图并分别确认清理。Comfy 原始执行耗时为 **51.47 秒、50.66 秒**，均为 Ref2VA 裸基座六步，随后各执行一次约 0.02 秒的无采样维护图。任务清理后，无法从残留历史独立还原这两次的尺寸、帧数或种子。两次耗时不直接与上表 Turbo 混合参考比较。

保密输入与请求保存在容器盘的 data-private，Comfy 使用随机子目录，成片本地临时提供播放和下载，默认 3600 秒，到期或主动确认后清理。共享权重缓存由维护图按签名保留；普通作业继续走原有持久化路径。收尾前用户另行确认已手动清理剩余成片。原始路径模板、SQLite 字段和故障恢复流程见[保密模式说明](RUNPOD_PRIVATE_UPLOAD.md)。

PNG 合成图已覆盖。前后端接受 PNG/WebP，后端解码验证实际格式，保密上传使用替代文件名和随机路径。尚无逐文件证据证明这两次实际采用的编码格式；WebP 变体、中文原名、浏览器传输和透明通道的完整矩阵未测。素材索引、图绑定和提交成功不能证明三张图片都对成片产生可辨识的条件影响。第三方 LoRA 已登记，当前部署未配置对应的 API 工作流，也未验证该权重在真实 GPU 上的效果。已验证的小型 CPU LoRA 切换检查覆盖 A、裸基座、B、裸基座的权重相等性。

## 存储和迁移

八个实际权重合计 78,646,097,621 字节（73.24 GiB），原位保存在 /workspace/models。现场 du 约为 Studio venv 140 MiB、Comfy venv 1.4 GiB、Node 189 MiB、前端依赖 183 MiB、dist 1.1 MiB，普通成片目录 3.9 MiB，普通快照目录 6.2 MiB。主归档包含两个 venv、Node、约束及 dist；配套目录另存固定 Comfy 检出、前端依赖/锁文件、部署键、四组实际工作流和 bindings、模型及路由清单。FoxMotion 源码以 GitHub 为基准。已完成迁移后的实际推理回归；本次收尾恢复验证限定在同一镜像的隔离目录，未更换另一台主机。重启后显存需要重新加载。
